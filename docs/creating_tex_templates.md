# Comprehensive Guide: Creating Dynamic .tex Templates

This document provides a clear, step-by-step explanation and set of guidelines for converting a static LaTeX design into a dynamic Jinja2 template (`.tex` file) for the PDF Generator pipeline.

---

## 1. Overview of the Process

Creating the `.tex` file is the second half of adding a new journal template (the first half being the `Apps/template_configs/<brand>.py` configuration, as detailed in `creating_new_template.md`).

The process generally looks like this:
1. **Acquire the static LaTeX design**: You usually start with a static `.tex` file containing dummy text and hardcoded graphics.
2. **Clean the Preamble**: Make the template compatible with the pipeline's XeLaTeX compiler.
3. **Inject Variables**: Replace the hardcoded text (title, authors, body, etc.) with Jinja2 `\VAR{...}` markers.
4. **Build the Reference Loop**: Use `\BLOCK{...}` to iterate over the generated references.
5. **Fix Image Paths**: Adjust paths to work within the pipeline's compilation environment.

---

## 2. Preamble & XeLaTeX Compatibility

**The Problem:** Raw LaTeX designs often come configured for `pdfLaTeX`, using legacy 8-bit encoding packages (e.g., `inputenc`, `fontenc`, `newtxmath`, `babel`). The PDF Generator pipeline compiles all templates using **XeLaTeX**, which uses `fontspec` and `polyglossia`. If you leave the `pdfLaTeX` packages in the template, XeLaTeX will crash during compilation.

**Step-by-step Solution:**
1. **Remove legacy packages:** Delete `\usepackage[utf8x]{inputenc}`, `\usepackage[T1]{fontenc}`, `\usepackage{newtxtext}`, `\usepackage{babel}`, and any `\DeclareUnicodeCharacter` commands.
2. **Inject the Dynamic Preamble:** The pipeline automatically generates the correct XeLaTeX font configurations (`polyglossia` + `fontspec`). You **must** include this tag immediately after `\documentclass`:
    ```latex
    \documentclass{article}
    \VAR{preamble | safe}
    ```
3. **Fix inline font commands:** Replace legacy font switching commands like `\usefont{T1}{phv}{bx}{n}\selectfont` with standard LaTeX equivalents that work with `fontspec` (e.g., `\sffamily\bfseries\selectfont` or `\rmfamily`).

## 3. Dynamic Variables (`\VAR{...}`)

The pipeline replaces Jinja2 variables (using the `\VAR{...}` syntax) with real data generated by the LLM or calculated by the pipeline. 

### Filtering & Escaping
Almost all text variables must be escaped so special characters (like `&`, `%`, `$`) don't break LaTeX. 
Always use: `\VAR{variableName | latex_escape | safe}`.
*Only omit `latex_escape` for URLs, DOIs, or pre-formatted LaTeX strings.*

### Common Variables and Typical Placement

Here is a guide to the most common variables based on the architecture of templates in `Apps/templates`:

| Variable | Description | Typical Placement |
| :--- | :--- | :--- |
| `\VAR{journalName}` | The full name of the journal. | Top header, often right-aligned or near the logo. |
| `\VAR{shortJournalName}` | Abbreviated journal name. | Headers, footers, or citations blocks. |
| `\VAR{type}` | The article type (e.g., "Research Article"). | Top left or right header area. |
| `\VAR{volume}`, `\VAR{issues}`, `\VAR{year}`, `\VAR{pdfNo}` | Metadata for the publication. | Often combined in a header/footer string like: `Vol. \VAR{volume} (\VAR{issues}), pp. \VAR{pdfNo} \VAR{year}` |
| `\VAR{doi}` | The DOI string. | Under the title or in the footer. |
| `\VAR{parentLink \| safe}` | URL for the journal/DOI. | Used inside `\href{\VAR{parentLink \| safe}}{\VAR{doi}}` |
| `\VAR{title}` | The main article title. | Top center/left, large bold font. |
| `\VAR{author \| safe}` | The list of authors. | Right below the title. Note: sometimes pipeline already escapes it, but `safe` is needed. |
| `\VAR{authorsDepartment}` | The author affiliations. | Below the author names. |
| `\VAR{received}`, `\VAR{editorAssigned}`, `\VAR{reviewed}`, `\VAR{revised}`, `\VAR{published}` | Manuscript processing dates. | Usually grouped at the very bottom of the first page or end of the document. |
| `\VAR{lang_name}` | The document language. | Used to wrap sections: `\begin{otherlanguage}{\VAR{lang_name}} ... \end{otherlanguage}` |

### Body Sections (LLM Generated)

The LLM generates the core text. Based on `pipeline_service.py`, the following variables map to the body sections:

*   `\VAR{abstract}`: Placed in the abstract box at the top of the first page.
*   `\VAR{keywords}`: Placed immediately below the abstract.
*   `\VAR{introduction}`: Start of the two-column layout.
*   `\VAR{description}`: Follows the introduction.
*   `\VAR{conclusion}`: **Important Note:** In the LLM prompt, you must ask for the `"discussion"` key to satisfy the backend, but the pipeline maps the LLM's `"summary"` output to the `\VAR{conclusion}` variable for the template!
*   `\VAR{discussion}`: The LLM's `"discussion"` output.

*Best Practice:* Wrap all body sections in language blocks to ensure correct hyphenation:
```latex
\begin{otherlanguage}{\VAR{lang_name}}
\noindent \VAR{introduction | latex_escape | safe}
\end{otherlanguage}
```

## 4. The Reference Loop (`\BLOCK{...}`)

References are passed as a dictionary called `content`. You must iterate through them using Jinja2 `\BLOCK{}` syntax to build the reference list.

**Typical Implementation:**
```latex
\section*{REFERENCES}

\BLOCK{ if content|length == 0 }
    \noindent No references generated.
\BLOCK{ else }
\BLOCK{ for key, item in content.items() }
\noindent\hangindent=1em\hangafter=1
\VAR{item.authors_short | latex_escape | safe} (\VAR{item.published}).
\BLOCK{ if item.url }
    \href{\VAR{item.url | safe}}{\VAR{item.title | latex_escape | safe}.}
\BLOCK{ else }
    \VAR{item.title | latex_escape | safe}.
\BLOCK{ endif }
\textit{\VAR{item.journalShortName | latex_escape | safe}},
\BLOCK{ if item.issues }
    \VAR{item.volume}(\VAR{item.issues}), \VAR{item.pageRangeOrNumber}.
\BLOCK{ else }
    \VAR{item.volume}, \VAR{item.pageRangeOrNumber}.
\BLOCK{ endif }

\BLOCK{ endfor }
\BLOCK{ endif }
```

## 5. Image and Logo Paths

**The Problem:** When building the template, you might test it in the `Apps/templates/` folder and use a path like `../Logo/image.png`. However, during production, the pipeline copies the `.tex` file and compiles it inside a deeply nested working directory (`Apps/DB/PDFStorePulsus/<journal_id>/`).

**The Solution:**
To reference images in the `Apps/Logo/` directory from the compilation directory, you must go up **three levels**. Always use the following path structure:
```latex
\includegraphics[width=60pt]{../../../Logo/YourJournalLogo.png}
```
*(Or if dynamic: `../../../Logo/\VAR{imgPath}`)*

## 6. Development Workflow (For AI Assistants & Developers)

1. **Initialize properly**: When creating a new `.tex` file from scratch, always use full file write operations (like `write_to_file`) to populate the initial structure. Do not create an empty file and try to use `replace_file_content` (it will fail because there's no target text).
2. **Migrate sections carefully**: It is highly recommended to look at an existing, working template (like `omics.tex` or `hilaris.tex`) and copy their reference loops (`\BLOCK`) and date metadata sections, as these rarely change structurally between journals.
3. **Test compilation**: If the pipeline crashes on `Step 10 : Create PDF file`, the issue is almost always in the LaTeX syntax (unescaped characters, missing packages, or XeLaTeX incompatibilities).
